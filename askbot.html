Slack 질문 Agent — 누구나 근거와 함께 묻는다

QA 지식관리시스템(CASE-01)에 쌓인 정책 · 이슈 · 기획을 근거로, 개발자든 기획자든 Slack에서 멘션 한 번으로 물어보고 스레드로 답을 받는 Claude 기반 질문 에이전트입니다. 답에는 항상 원본 링크가 붙고, 자료에 없으면 “모른다”고 답합니다.

Problem

지식을 한 곳에 모아도 Obsidian · Git을 쓰는 QA만 볼 수 있으면, “이거 정책이 뭐예요?”라는 질문은 여전히 QA 한 사람에게 몰립니다.

Action

팀이 이미 있는 Slack에 읽기 전용 에이전트를 붙이고, 답 형식 · 권한 · “모른다” 규칙을 설계해 Linux 서버에서 무인으로 운영했습니다.

Result

누구나 멘션 한 줄로 약 15초 안에 근거 링크가 붙은 답을 받고, 매일 아침 팀 채널에 새 버그 · 기획 변경 · 확정 정책이 공지됩니다.

제 판단과 기여

역할 · 단독 설계 · 구현 · 서버 배포 · 운영

  1. 답 형식을 고정하고, 자료에 없으면 “모른다”고 답하게 했습니다. — 그럴듯한 답이 한 번 틀리면 팀은 봇을 다시 쓰지 않습니다.
  2. 읽기 전용으로, 조회 스크립트 하나만 허용했습니다. — 누구나 말을 거는 봇에서는 권한이 곧 사고 범위입니다.
  3. QA가 답하던 질문을 팀이 직접 확인하게 만드는 것을 목표로 잡았습니다. — 지식을 모아도 QA만 볼 수 있으면 질문은 계속 QA 한 사람에게 몰립니다.

스레드 답변결론 · 근거 링크 · 다음 할 일

위 스레드에서 “불러오기 할 때 태스크 화면에 X 표시가 떠야 해?”라는 질문에, 봇은 Figma 시안 위치와 정책 카드를 근거로 답하면서도, 댓글에 남은 “팝업 닫기로 변경”이 실제 중단인지는 ❓ 미확인으로 남기고 기획에 확인하라는 다음 할 일을 제시합니다.

왜 Slack인가 사용자가 이미 쓰는 도구 안에서 동작해야 쓰입니다. 개발 · 기획에게 새 도구를 열게 하는 대신, 팀이 하루 종일 있는 Slack으로 지식을 가져갔습니다.
답변 설계 — 믿고 쓸 수 있는 답결론 먼저 · 근거 링크 · 모르면 모른다

답 형식을 고정했다

① 결론✅ 답 · ⚠️ 주의 · 🔍 자료 없음 · 🙅 거절
→
② 핵심 정보시안 · 정책 · 이력
→
③ 원본 링크최대 3개
→
④ 다음 할 일누구에게 무엇을 확인
  • 첫 줄만 읽어도 된다 — 결론 이모지로 답의 성격을 바로 구분
  • 자료에 없으면 “모른다” — 🔍로 표시하고, 찾아본 곳과 물어볼 곳을 함께 안내
  • 확인 안 된 건 확인 안 됐다고 — 정책 문서에 없는 동작은 ❓ 미확인
  • 근거 링크 — Figma 시안 · 정책 노트 · 티켓으로 바로 가서 직접 확인 가능
왜 이렇게 “모른다”고 말하게 하는 설계가 신뢰를 만듭니다. 그럴듯한 답이 한 번 틀리면 팀은 봇을 다시 쓰지 않습니다. 근거 링크와 미확인 표시가 있어야 개발 · 기획이 답을 믿고 그대로 쓸 수 있습니다.
권한 설계 — 질문 전용 에이전트최소 권한 · 작업 요청 거절

누구나 말을 걸 수 있는 봇이기 때문에, 무엇을 할 수 있는지보다 무엇을 못 하게 할지를 먼저 정했습니다.

🔒 읽기 전용

파일 수정 · 외부 쓰기 · 커넥터를 모두 차단하고, 조회 스크립트 하나만 허용했습니다. 누가 무엇을 요청해도 저장소와 ClickUp은 바뀌지 않습니다.

🙅 작업 요청은 거절

“티켓 만들어줘”, “TC 고쳐줘” 같은 요청은 🙅로 거절하고 담당자를 안내합니다. 쓰기는 승인 흐름이 있는 동기화 쪽에서만 일어납니다.

🔑 인증 분리

ClickUp · Figma는 API 토큰으로 조회해 AI 계정 인증과 분리했습니다. AI 세션이 만료돼도 조회는 계속됩니다.

⚡ 경량 모델

질문 응답은 판단보다 조회와 요약이 중심이라 Haiku를 써서 약 15초 안에 답하게 했습니다.

왜 이렇게 권한을 넓게 열어두면 편하지만, 누구나 말을 걸 수 있는 봇에서는 권한이 곧 사고 범위입니다. 질문 봇은 읽기만, 쓰기는 사람이 승인하는 동기화만 — 역할에 따라 권한을 분리했습니다.
팀 데일리 공지팀에 쓸모 있는 것만

매일 아침 동기화가 끝나면 팀 채널에 새 버그 · 해결 · 기획(Figma) 변경 · 새로 확정된 정책만 짧게 올립니다. QA 내부 정보(승인 대기, TC 공백 등)는 뺍니다.

  • 버그는 티켓 링크와 심각도를 붙여 한 줄씩
  • 기획 변경은 Figma에서 감지한 문구 변경을 사람이 읽을 수 있는 문장으로
  • 새로 확정된 정책은 근거 티켓과 결정자를 함께
  • 마지막에 “궁금한 건 봇에게 물어보세요” — 공지가 질문으로 이어지게
